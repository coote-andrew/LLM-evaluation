Choosing how to score answers

An evaluation config is a reusable scoring recipe. After a model run finishes, apply a config to mark each row correct or incorrect.

Keyword match

In plain English: “Does the answer mention X?” or “Does this JSON field equal Y?”

Best for smoke tests, required phrases, checking a key exists.

Field match

In plain English: “Compare each JSON field to the expected value in my spreadsheet.”

Exact = text must match. LLM judge = another model decides if meaning matches when wording differs.

Python script

In plain English: “I’ll write a short rule myself for what counts as correct.”

Best for domain rules the other types can’t express (lists, regex, API lookups).

AI judge

In plain English: “Ask another AI to mark this answer right or wrong.”

Best for free-text where meaning matters more than exact wording.

Human review

In plain English: “A person clicks through each row and scores it.”

Best for gold standards, calibration, and nuanced edge cases.

Keyword match — check reference

Each check runs independently and produces a true / false result. All checks are reported; a row is considered fully correct only when every check passes.

Response contains phrase contains_phrase

Searches the entire raw model response (as plain text) for the phrase. Works for both JSON and prose responses.

Fields: phrase — the text to look for
Response
The patient has diabetes and hypertension.
Check
{"type":"contains_phrase","name":"mentions diabetes","phrase":"diabetes"}
✓ true — "diabetes" found in response
Negative example
The patient has hypertension only.
Same check
{"type":"contains_phrase","name":"mentions diabetes","phrase":"diabetes"}
✗ false — "diabetes" not present
JSON key exists json_key_exists

Checks whether a key with the given name appears anywhere in the JSON response. Does not care about the value — only that the key is present.

Fields: key — the key name to look for
Response
{"diagnosis": "diabetes", "confidence": 0.95}
Check
{"type":"json_key_exists","name":"has diagnosis key","key":"diagnosis"}
✓ true — key "diagnosis" exists
Negative example
{"condition": "diabetes", "confidence": 0.95}
Same check
{"type":"json_key_exists","name":"has diagnosis key","key":"diagnosis"}
✗ false — "diagnosis" not present ("condition" is a different key)
JSON value exists anywhere json_value_exists

Checks whether a phrase appears in any value anywhere in the JSON response. Useful when you know what the value should contain but not which key it will be under.

Fields: phrase — the text to search for within values
Response
{"result": {"label": "type 2 diabetes", "icd": "E11"}}
Check
{"type":"json_value_exists","name":"diabetes mentioned","phrase":"diabetes"}
✓ true — "diabetes" found inside value "type 2 diabetes"
Negative example
{"result": {"label": "hypertension", "icd": "I10"}}
Same check
{"type":"json_value_exists","name":"diabetes mentioned","phrase":"diabetes"}
✗ false — "diabetes" not found in any value
JSON field contains phrase json_key_contains

Reads the value at a specific dot-notation path and checks whether it contains the phrase. Use this when you know exactly which key to inspect.

Fields: json_path — dot-notation path e.g. diagnosis or result.label  ·  phrase — text to find in that value
Response
{"diagnosis": "type 2 diabetes mellitus"}
Check
{"type":"json_key_contains","name":"diagnosis has diabetes","json_path":"diagnosis","phrase":"diabetes"}
✓ true — value at "diagnosis" contains "diabetes"
Negative example
{"diagnosis": "hypertension"}
Same check
{"type":"json_key_contains","name":"diagnosis has diabetes","json_path":"diagnosis","phrase":"diabetes"}
✗ false — value at "diagnosis" does not contain "diabetes"
JSON field equals value json_key_equals

Reads the value at a specific path and checks for an exact match. Good for boolean flags or controlled vocabulary where partial matches aren't sufficient.

Fields: json_path — dot-notation path  ·  expected_value — the exact value to match
Response
{"correct": true}
Check
{"type":"json_key_equals","name":"is correct","json_path":"correct","expected_value":true}
✓ true — value at "correct" equals true
Negative example
{"correct": false}
Same check
{"type":"json_key_equals","name":"is correct","json_path":"correct","expected_value":true}
✗ false — value does not match

Field match — how it works

The LLM is asked to return a JSON object. Each declared field is compared against the corresponding output_* expected value from the CSV row. Every declared field produces a boolean pass/fail in the assessment.

Exact match
String equality

The actual value (from the LLM's JSON) is compared to the expected value (from the CSV) as strings. Case-insensitive by default.

{"name": "output_label", "match_type": "exact"}
LLM judge
Semantic equivalence

A judge LLM is asked whether the actual and expected values are equivalent. Useful for free-text or paraphrased answers.

{"name": "output_summary", "match_type": "llm_judge"}
Example — CSV has columns: input_text, output_label, output_confidence
Prompt: "Given: {input_text} — Return JSON: {output_label, output_confidence}"
LLM response: {"output_label": "positive", "output_confidence": "high"}
CSV expected:  output_label=positive, output_confidence=high
Result: output_label ✓  output_confidence ✓  → row correct

Python script — reference

Your script runs once per row in a restricted Python environment. Assign a dict to result before the script ends. Boolean values count toward accuracy scoring; strings and integers are stored for display.

Variables injected per row
input_fields dict — values from every input_* column for this row
e.g. {"input_note": "…", "input_unit": "ED"}
expected_output_fields dict — ground-truth values from every output_* column
e.g. {"output_label": "positive", "output_codes": "73211009"}
raw_response str — the model's raw text output exactly as returned
response_parsed dict / list / None — pre-parsed JSON from the response, or None if the response is not valid JSON
Rules & environment
  • Must assign a dict to result
  • Boolean values → used for accuracy scoring
  • Integer / string values → stored, not scored
  • Exceptions are caught and stored in the row's notes — the row is not counted as correct
  • Available modules: json, re, math, datetime, requests, urllib
  • No import, no file I/O, no subprocesses

Common patterns

Compare a JSON field to the expected CSV value field match

The model returns a JSON object. Pick a field out of it and compare against the ground-truth column from the CSV.

CSV columns: input_note, output_label
Model response
{"label": "positive", "confidence": 0.92}
Script
parsed = response_parsed or {}
actual  = str(parsed.get("label", "")).strip().lower()
expected = expected_output_fields.get("output_label", "").strip().lower()

result = {
    "label_correct": actual == expected,
    "confidence": parsed.get("confidence"),   # stored, not scored
}
✓ label_correct = True when labels match
Tip — accessing input data
# The original note text is also available:
note = input_fields.get("input_note", "")
# Useful if you want to cross-check the response
# against something in the input.
Check every item in a JSON list list validation

The model returns a list of values (e.g. diagnosis codes). Verify that the expected value appears somewhere in the list, or that every item in the list meets a condition.

Model response
{"diagnoses": ["73211009", "44054006", "38341003"]}
Script — expected code present in list
parsed   = response_parsed or {}
codes    = parsed.get("diagnoses", [])
expected = expected_output_fields.get("output_primary_code", "")

result = {
    "primary_code_present": expected in codes,
    "code_count": len(codes),
}
Script — all codes look like SNOMED (numeric, 6–18 digits)
parsed = response_parsed or {}
codes  = parsed.get("diagnoses", [])

all_numeric = all(re.fullmatch(r"\d{6,18}", str(c)) for c in codes)

result = {
    "primary_code_present": expected_output_fields.get("output_primary_code", "") in codes,
    "all_codes_numeric":    all_numeric,
    "code_count":           len(codes),
}
Validate against an external API (e.g. Ontoserver / FHIR) API lookup

Use requests to call an internal service for each code the model returns — for example, checking SNOMED CT concept validity against an Ontoserver instance. Keep calls targeted: one request per code or a single batch lookup.

Script — check each SNOMED code is a valid concept
ONTOSERVER = "https://ontoserver.example.org/fhir"

parsed = response_parsed or {}
codes  = parsed.get("snomed_codes", [])
if isinstance(codes, str):
    codes = [c.strip() for c in codes.split(",") if c.strip()]

def is_valid_snomed(code):
    url = f"{ONTOSERVER}/CodeSystem/$lookup"
    try:
        r = requests.get(url, params={
            "system": "http://snomed.info/sct",
            "code":   code,
        }, timeout=5)
        return r.status_code == 200
    except Exception:
        return False

valid_flags = {str(c): is_valid_snomed(str(c)) for c in codes}
all_valid   = all(valid_flags.values()) if valid_flags else False

result = {
    "all_codes_valid": all_valid,
    "valid_detail":    json.dumps(valid_flags),   # stored as text
}
Script — single batch ValueSet $validate-code
ONTOSERVER = "https://ontoserver.example.org/fhir"
VS_URL = "http://snomed.info/sct?fhir_vs=refset/32570581000036105"

parsed = response_parsed or {}
code   = str(parsed.get("snomed_code", "")).strip()

result_flag = False
detail = ""
if code:
    try:
        r = requests.get(
            f"{ONTOSERVER}/ValueSet/$validate-code",
            params={"url": VS_URL, "code": code,
                    "system": "http://snomed.info/sct"},
            timeout=5,
        )
        body = r.json()
        result_flag = any(
            p.get("name") == "result" and p.get("valueBoolean")
            for p in body.get("parameter", [])
        )
        detail = code
    except Exception as e:
        detail = str(e)

result = {
    "code_in_valueset": result_flag,
    "code_checked":     detail,
}
Pattern matching with re regex

Use the re module to apply regular expressions to the raw response or to individual fields extracted from the parsed JSON.

Check the response mentions an ICD-10 code
icd10_pattern = r"\b[A-Z]\d{2}(?:\.\d{1,4})?\b"
matches = re.findall(icd10_pattern, raw_response)

result = {
    "has_icd10_code": len(matches) > 0,
    "first_code":     matches[0] if matches else "",
}
Check a date field is ISO-8601
parsed = response_parsed or {}
date_str = str(parsed.get("date", ""))
is_iso = bool(re.fullmatch(r"\d{4}-\d{2}-\d{2}", date_str))

result = {"date_is_iso8601": is_iso}

AI judge — output field reference

The judge model receives your prompt (with {input}, {output}, {expected} substituted) and must respond with JSON. Define the fields you expect it to return.

Boolean
true / false

Used for accuracy scoring. The judge should return true or false.

{"name":"correct","type":"boolean","label":"Is the answer correct?"}
Integer
Numeric score

Judge returns a number. Define a min/max for display context.

{"name":"score","type":"integer","label":"Quality score","min":0,"max":10}
Text
Free text

Judge returns a string, e.g. a brief justification.

{"name":"reason","type":"text","label":"Justification"}
Example judge prompt
You are an expert evaluator. Given:

Input: {input}
Model output: {output}
Expected output: {expected}

Respond with JSON only:
{"correct": true/false, "score": 0-10, "reason": "one sentence"}
